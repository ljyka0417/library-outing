# 도서관 지도

가이드북(종이책)과 QR로 이어지는 도서관 안내 앱.

앱 이름은 「도서관 지도」, 인쇄 가이드북 제목은 「전국 도서관 나들이」다.
둘을 나눈 이유는 검색이다. 앱스토어에서 "전국 도서관 나들이" 는 검색 결과가
0 건이라 그 말로는 아무도 찾아오지 못한다. "도서관 지도" 는 같은 이름의 앱이
없어 등록도 가능하고, "도서관" 검색에도 걸린다.
책에서 도서관을 발견 → QR 스캔 → 앱에서 상세정보 확인 → 지도앱으로 길찾기 →
주변 맛집·카페·문화시설까지 하나의 나들이 코스로 완성합니다.

## 현재 상태

MVP 1차 스캐폴딩 완료. **졸업작품 선정 도서관 132곳으로 전체 화면 흐름이 동작합니다.**
API 키 없이 바로 실행해서 기획 검증이 가능합니다.

```bash
npm run check-data
```

도서관 데이터의 id/이름 중복, 분류 누락, 지역별·주제별 분포를 점검합니다.

### 데이터 현황

| | 상태 |
|---|---|
| 도서관명 · 지역 · 특화 태그 · 주제 분류 | ✅ 132곳 |
| 주소 | ✅ 120곳 (91%) |
| 전화번호 | ✅ 118곳 (89%) |
| 좌표 | ✅ 121곳 (92%) |
| 주변 맛집·카페·문화시설 | ✅ 119곳 / **1,881개 장소** |
| 운영시간 · 휴관일 | ⬜ 정보나루 인증키 승인 대기 |

주소·전화·좌표는 카카오 로컬 API(`npm run geocode`)로 채웠습니다.
운영시간은 카카오가 제공하지 않아 정보나루(`npm run enrich`)가 필요합니다.

현황은 앱의 **마이페이지 하단**에서도 실시간으로 볼 수 있습니다 (개발 빌드에서만).

확인되지 않은 값을 그럴듯하게 채우면 앱이 틀린 정보를 단정적으로 말하게 됩니다.
비워 두면 화면이 해당 항목을 조용히 숨기고, 대신 "상세 정보는 준비 중이에요"를
띄우도록 만들었습니다. 실제 공공 도서관 데이터도 구멍이 많으므로 이 구조가
실 API 연동 후에도 그대로 쓰입니다.

**좌표가 없어도 지도 연결은 정확히 동작합니다.** 좌표 대신 도서관명으로
검색해서 열기 때문입니다. "서울도서관" 같은 고유한 이름은 오히려 근사 좌표보다
정확합니다.

| 항목 | 상태 |
|---|---|
| 홈 / 주제별 카테고리 / 검색 · 필터 | ✅ |
| 도서관 상세 (정보·추천도서·주변정보) | ✅ |
| 네이버지도 / 카카오맵 딥링크 + 폴백 | ✅ |
| QR 딥링크 라우팅 | ✅ |
| 즐겨찾기 · 최근 본 · 방문기록 (로컬 저장) | ✅ |
| 오프라인 캐시 (마지막 조회 결과 유지) | ✅ |
| 실 API 연동 (정보나루 / 카카오 로컬) | ⬜ 인터페이스만 준비 |
| 로그인 · 서버 동기화 | ⬜ 2차 |

## 도서관 상세 정보 채우기

이름·지역·특화 태그는 채워져 있지만 주소·전화·운영시간은 비어 있습니다.
아래 순서로 채웁니다.

```bash
npm run enrich
```

정보나루 API에서 전국 도서관을 받아 우리 132곳과 이름·지역으로 매칭한 뒤
`src/data/libraries.enriched.json` 에 주소·전화·홈페이지·좌표·휴관일·운영시간을 씁니다.

**데이터가 세 곳에서 오고, 뒤쪽이 앞쪽을 덮습니다:**

| 출처 | 내용 | 관리 주체 |
|---|---|---|
| `libraries.mock.ts` 의 `SEEDS` | 이름·지역·특화 태그·분류 | **사람** (편집 결정) |
| `libraries.enriched.json` | 주소·전화·좌표·운영시간 | 자동 생성 (덮어씀) |
| `libraries.manual.json` | 위와 같음 | **사람** (가장 우선) |

편집 정보와 사실 정보를 나눠 둬서, 수집을 다시 돌려도 분류·특화 태그 같은
편집 결정이 날아가지 않습니다.

정보나루는 공공도서관 위주라 작은도서관·사립·전문도서관(농심식문화전문도서관,
브라이튼도서관, 법원도서관 등)은 매칭이 안 됩니다. 그 목록이
`libraries.unmatched.csv` 로 나오니, 각 도서관 홈페이지에서 찾아
`libraries.manual.json` 에 넣으면 됩니다.

## 사진에 대하여

**랜덤 이미지를 쓰지 않습니다.** 예전엔 picsum 랜덤 사진을 넣었는데,
우리소리도서관에 해변 사진이 뜨는 식이었습니다. 스토어에 올릴 앱이 엉뚱한
건물을 "그 도서관"인 양 보여주면 사용자를 속이는 것이라 전부 걷어냈습니다.

지금은 사진이 없으면 **주제 색 + 달곰이 플레이스홀더**가 나옵니다.
목록에서 분류가 한눈에 구분되는 부수 효과도 있습니다.

### 실사진 넣는 법

1. `assets/libraries/{도서관id}.jpg` 로 저장
2. `src/data/libraryPhotos.ts` 의 `PHOTOS` 에 한 줄 추가
3. 끝 — 카드·상세가 자동으로 실사진을 씁니다

### 사진 구하는 경로 (저작권 확인 필수)

| 경로 | 상업적 이용 | 비고 |
|---|---|---|
| 직접 촬영 | ✅ | 가장 확실. 랜드마크 20곳만으로도 인상이 달라집니다 |
| 도서관에 요청 | ✅ (허락 시) | 공공도서관은 홍보용 사진 제공에 대체로 협조적 |
| 공공누리 1·2유형 | ✅ (출처표시) | 각 기관 사이트에서 유형 표시 확인 |
| Wikimedia Commons | ✅ (라이선스 준수) | 출처·라이선스 표기 의무 |
| 도서관 홈페이지 무단 사용 | ❌ | 공공누리 표시 없으면 저작권 침해 |
| 지도앱 장소 사진 스크래핑 | ❌ | 약관 위반 |
| Unsplash 등 "도서관스러운" 사진 | ❌ | 그 도서관이 아니면 사용자 기만 |

**주변 장소 사진은 카카오 로컬 API가 제공하지 않습니다.** 종류별 색·아이콘
카드로 대체했습니다.

**책 표지도 넣지 않습니다.** 출판사 표지는 저작물입니다. 필요하면
알라딘/교보 OpenAPI 로 ISBN 기반 표지를 받아 `Book.coverImageUrl` 을 채우면
`BookCard` 가 자동으로 씁니다.

## QR 딥링크 테스트

```bash
npm run qr
```

`qr-sheet.html` 이 생성됩니다. 브라우저로 열면 도서관 16곳 × 3종류의 QR이 나오고,
상단 탭으로 종류를 바꿀 수 있습니다.

| 종류 | 값 | 언제 쓰나 |
|---|---|---|
| **인쇄용** | `https://library-outing.kr/library/{id}` | 실제 가이드북에 인쇄 |
| **Expo Go 테스트용** | `exp://{LAN_IP}:8081/--/library/{id}` | 개발 중 실기기 확인 |
| **네이티브 빌드용** | `libraryapp://library/{id}` | 개발빌드·스토어 배포본 |

### ⚠️ Expo Go 는 커스텀 스킴을 받지 못합니다

`libraryapp://` 은 **네이티브 빌드에서만** 동작합니다. Expo Go 로 테스트할 때는
반드시 `exp://` 형식을 써야 하며, QR 시트의 "Expo Go 테스트용" 탭이 그 값입니다.
휴대폰이 PC와 같은 Wi-Fi 에 있어야 하고, `npx expo start` 가 켜져 있어야 합니다.

LAN IP 가 바뀌면 `npm run qr` 을 다시 돌리면 됩니다.

네이티브 빌드에서 스킴을 직접 확인하려면:

```bash
npx uri-scheme open "libraryapp://library/seoul-music" --android
```

### 책자에 인쇄할 QR 값

**앱 스킴(`libraryapp://`)을 그대로 인쇄하면 안 됩니다.** 앱 미설치 사용자에게는
오류만 뜹니다. 웹 URL을 인쇄해서 App Link로 앱이 가로채도록 해야 합니다.

```
https://library-outing.kr/library/{도서관ID}
```

자세한 내용은 `src/utils/deepLink.ts` 주석 참고.

## 설계 노트

**지도를 직접 렌더링하지 않습니다.** 네이버지도·카카오맵으로 넘겨주면 길찾기,
대중교통, 즐겨찾기를 전부 사용자가 이미 쓰는 앱에서 해결할 수 있습니다.
지도 SDK 키 발급·과금·네이티브 모듈이 전부 불필요해집니다.

**API 계층이 인터페이스로 추상화되어 있습니다.** 화면 코드는 `libraryApi` /
`nearbyApi` 인터페이스에만 의존하므로, 나중에 Firebase든 자체 서버든 붙일 때
`src/api/` 안의 구현체만 채우면 됩니다.

**로그인 없이 동작합니다.** 즐겨찾기·방문기록이 전부 기기에 저장되므로 첫 진입
장벽이 없습니다. 로그인은 2차에서 "기기 간 동기화"라는 명확한 이득과 함께 붙입니다.

## 실기기 빌드 (EAS)

Windows 에서도 됩니다. Expo 클라우드의 macOS 가 대신 빌드합니다.

### 처음 한 번만

```bash
npx eas login
```

Expo 계정이 필요합니다(무료). 없으면 https://expo.dev 에서 가입하세요.

```bash
npx eas init
```

프로젝트를 Expo 에 등록하고 `app.json` 에 `extra.eas.projectId` 를 넣어 줍니다.

### 개발빌드 만들기 — QR 딥링크 검증용

**`libraryapp://` 딥링크는 Expo Go 에서 동작하지 않습니다.** 책 QR 흐름을
실기기에서 검증하려면 개발빌드가 필요합니다.

```bash
npm run build:android
```

```bash
npm run build:ios
```

> **Android 는 지금 바로 됩니다 — Apple 개발자 등록이 필요 없습니다.**
> APK 링크가 나오면 폰에서 다운받아 설치하면 끝입니다.
> iOS 실기기 빌드는 Apple Developer Program(연 $99) 가입이 있어야 합니다.
> **딥링크 검증이 목적이라면 Android 로 먼저 하는 게 빠릅니다.**

빌드된 앱을 설치한 뒤 개발 서버를 켜고 QR 시트로 테스트합니다.

```bash
npx expo start --dev-client
```

`npm run qr` 로 만든 시트의 **"네이티브 빌드용"** 탭 QR 을 찍으면
해당 도서관 상세 화면으로 바로 들어가야 합니다.

### 빌드 프로파일

| 프로파일 | 용도 | 산출물 |
|---|---|---|
| `development` | 딥링크·스플래시 검증. 개발 서버 연결 필요 | APK / ipa |
| `preview` | 발표 시연·지인 테스트. 서버 없이 단독 실행 | APK / ipa |
| `production` | 스토어 제출 | AAB / ipa |

```bash
npm run build:preview
```

발표용으로는 이게 가장 편합니다. 개발 서버 없이 폰에서 단독으로 돕니다.
